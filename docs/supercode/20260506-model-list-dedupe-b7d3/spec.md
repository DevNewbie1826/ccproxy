# Work ID

20260506-model-list-dedupe-b7d3

# Objective

Make `GET /v1/models` on the local proxy (`http://localhost:8317/v1/models`) return a de-duplicated, canonical model list while preserving compatibility for clients that submit short alias model IDs such as `glm-4.7` or `MiniMax-M2.7`.

# Current State

- `ThinkingProxy` listens on port `8317` and forwards requests to CLIProxyAPI on port `8328`.
- The `/v1/models` response is produced by the bundled CLIProxyAPI backend, not by Swift endpoint code in this repository.
- `ThinkingProxy` currently modifies selected POST request bodies and streams backend responses unchanged.
- Provider/model configuration is generated in Swift as `claude-api-key` entries with provider prefixes such as `zai` and `minimax`.
- Current generated provider model lists contain short model IDs such as `glm-4.7`, `glm-5`, and `MiniMax-M2.7`; there is no existing alias field or alias resolver in this repository.
- Observed `/v1/models` output includes both prefixed and unprefixed forms for the same model family, for example `zai/glm-4.7` and `glm-4.7`, causing duplicate-looking entries.

# Desired Outcome

- `GET /v1/models` through port `8317` should expose only canonical model IDs for duplicated provider-backed models.
- Canonical IDs should prefer provider-prefixed forms for third-party providers, for example:
  - `zai/glm-4.7` instead of also exposing `glm-4.7`
  - `minimax/MiniMax-M2.7` instead of also exposing `MiniMax-M2.7`
- Request compatibility should be preserved by accepting known short aliases in model request bodies and rewriting them to their canonical IDs before forwarding to CLIProxyAPI.
- Provider ownership metadata in filtered `/v1/models` responses should be normalized where the proxy can determine it from the canonical ID, for example `zai` for `zai/*`, `minimax` for `minimax/*`, and `openai` for `gpt-*` / `codex-*` models.
- Existing non-model-list proxy behavior should remain unchanged.

Canonical alias table for this work:

| Alias accepted in requests / removed from model list when canonical exists | Canonical model ID retained in `/v1/models` |
| --- | --- |
| `glm-5.1` | `zai/glm-5.1` |
| `glm-5` | `zai/glm-5` |
| `glm-5-turbo` | `zai/glm-5-turbo` |
| `glm-5v-turbo` | `zai/glm-5v-turbo` |
| `glm-4.7` | `zai/glm-4.7` |
| `glm-4.7-flash` | `zai/glm-4.7-flash` |
| `glm-4.6v` | `zai/glm-4.6v` |
| `glm-4.5-air` | `zai/glm-4.5-air` |
| `MiniMax-M2.7` | `minimax/MiniMax-M2.7` |

# Scope

In scope:

- Add a proxy-layer filter for successful `GET /v1/models` responses from CLIProxyAPI.
- De-duplicate model entries by canonical model identity while preserving valid OpenAI-compatible response shape.
- Add alias-to-canonical request rewriting for JSON request bodies containing a top-level `model` string.
- Cover exactly the aliases listed in the canonical alias table above.
- Add or update automated tests for response filtering and alias rewriting.

Out of scope:

- Modifying the bundled CLIProxyAPI backend binary or its source.
- Changing provider credential discovery, provider enable/disable behavior, or server lifecycle management.
- Adding UI controls for model alias management.
- Introducing a user-configurable alias registry.
- Changing model availability beyond removing duplicate aliases from the model-list response.

# Non-Goals

- Do not remove compatibility for existing clients that send short model names.
- Do not attempt to infer arbitrary aliases from every possible provider naming convention.
- Do not alias Kimi models in this work; no duplicate Kimi entry was shown in the user-provided `/v1/models` payload.
- Do not transform streaming completion/chat responses.
- Do not change the backend port (`8328`) or public proxy port (`8317`).

# Constraints

- The solution must live in the Swift proxy layer because `/v1/models` is generated by an external bundled backend.
- The filter must only rewrite complete JSON model-list responses when safe; malformed, non-JSON, or unexpected backend responses should pass through unchanged or fail safely without crashing the proxy.
- Duplicate detection is table-driven: an unprefixed alias entry is removed only when its canonical model ID from the table is also present in the same response. If the canonical entry is absent, keep the alias entry unchanged.
- If both alias and canonical entries exist but their non-`id` fields differ, retain the canonical entry as-is, normalize only fields explicitly covered below, and drop the alias entry.
- Ownership normalization is limited to retained canonical IDs with deterministic prefixes or known OpenAI naming: `zai/*` -> `owned_by: "zai"`, `minimax/*` -> `owned_by: "minimax"`, and IDs beginning `gpt-` or `codex-` -> `owned_by: "openai"`. Other retained entries keep their original `owned_by` value.
- Alias request rewriting applies only to JSON request bodies with a top-level string `model` field on methods that carry a body, primarily `POST`; it must not modify query strings, headers, or nested `model` fields.
- HTTP response headers must remain consistent with the transformed body, especially `Content-Length` and connection handling.
- Existing authorization behavior for requests through `ThinkingProxy` must remain intact.
- Existing thinking-parameter, cache-control stripping, Vercel gateway routing, and `/provider/` path normalization behavior must remain intact.

# Success Criteria

- Given the observed duplicate `/v1/models` payload, the proxy response contains one entry per canonical model and omits duplicate short aliases when a provider-prefixed canonical entry exists.
- Tests include a fixture based on the user-provided payload containing at least these duplicate pairs: `zai/glm-4.7` + `glm-4.7`, `zai/glm-4.7-flash` + `glm-4.7-flash`, `zai/glm-4.6v` + `glm-4.6v`, `zai/glm-4.5-air` + `glm-4.5-air`, `zai/glm-5.1` + `glm-5.1`, `zai/glm-5` + `glm-5`, `zai/glm-5-turbo` + `glm-5-turbo`, `zai/glm-5v-turbo` + `glm-5v-turbo`, and `minimax/MiniMax-M2.7` + `MiniMax-M2.7`.
- `zai/*` and `minimax/*` canonical entries are retained when both prefixed and unprefixed entries exist.
- OpenAI models such as `gpt-5.5` remain present and are not incorrectly prefixed.
- Known alias request models such as `glm-4.7` and `MiniMax-M2.7` are rewritten to `zai/glm-4.7` and `minimax/MiniMax-M2.7` respectively before forwarding.
- Alias entries without a corresponding canonical entry remain in the `/v1/models` response unchanged.
- Existing tests pass, and new tests cover the model-list filter and alias rewriting behavior.

# Risks / Unknowns

- CLIProxyAPI response format may vary; the proxy filter must be conservative and robust to unexpected fields.
- If CLIProxyAPI accepts only short IDs for some backend routes, canonical request rewriting could break those routes; this risk is bounded by using only the explicit alias table above and preserving canonical IDs shown by the backend model list.
- Response filtering in a streaming proxy requires buffering `/v1/models` responses, but this endpoint is expected to be small; other endpoints should continue streaming unchanged.
